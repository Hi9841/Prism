Executive Summary · Current State (v0.9.32)

An exhaustive inspection was conducted on Prism (v0.9.32) across the Rust backend (Tauri v2 + Win32 shell integration), the React 19 frontend palette, and the NTFS USN journal catalog.

Compared to historical audit baselines (v0.6.7), Prism has undergone massive architectural maturation: the file catalog has migrated to an atomic SQLite database with live NTFS change journal watching, Win-key hook polling was reduced from 50 ms to idle backoffs, the update checker was throttled, and apps cache writes are fully atomic.

This audit surfaces 9 concrete findings: 1 functional UI mouse interaction bug in context menu routing, 1 algorithmic O(N*M) linear scan in MFT system directory pruning, 2 thread-blocking/IPC performance hazards, 1 shared temp-file TOCTOU race in Explorer communication, and 4 design engineering and accessibility items.

High UI Interaction Bug Regressed in v0.9.30

src/features/palette/Palette.tsx:1009-1014
In ResultRow, the onContextMenu mouse handler explicitly guards context menu opening with: if (item.runAsAdmin || item.openLocation). Remediation: Replace the incomplete property check in Palette.tsx with hasResultActions(item), ensuring parity between keyboard and pointer triggers.
High Performance & Latency NTFS Catalog Sweep

O(N*M) linear search on system directory subtrees during NTFS MFT enumeration

src-tauri/src/catalog/ntfs/mft.rs:22, 54-59
During raw MFT enumeration via FSCTL_ENUM_USN_DATA, Prism filters out root-level system folders (like $Extend, $RECYCLE.BIN, System Volume Information) and all their child directories. However, system_subtrees is declared as a Vec<u64>. On volumes with deep or fragmented recycle bins and extensive system directories, system_subtrees accumulates thousands of directory File Reference Numbers (FRNs). Executing system_subtrees.contains(&record.parent_frn) for every record across drives with 1,000,000+ files causes billions of sequential comparisons and severe CPU cache thrashing on initial disk indexing.
- let mut system_subtrees: Vec<u64> = Vec::new(); + let mut system_subtrees: std::collections::HashSet<u64> = std::collections::HashSet::new(); ... - system_subtrees.push(record.frn); + system_subtrees.insert(record.frn);
Remediation: Convert system_subtrees from Vec<u64> to HashSet<u64> (or FxHashSet<u64>). This changes lookup cost from O(M) linear traversal per MFT entry to O(1) hash lookup.
Medium Performance & DWM Tauri IPC Hot Path

Synchronous main-thread Win32 positioning during window width easing animation

src/state/app.tsx:329-344 & src-tauri/src/lib.rs:1066-1083
When changing window width in Settings (e.g. 560px -> 720px), the frontend runs a 240 ms easing curve that calls setWindowWidth(next) on every requestAnimationFrame. Because set_window_width is a synchronous Tauri command running directly on the main UI thread, each frame executes multiple Win32 API calls: outer_size(), set_size(), GetCursorPos(), MonitorFromWindow(), GetMonitorInfoW(), and SetWindowPos(). Firing 15-30 synchronous Win32 calls across the IPC boundary in 240 ms creates micro-stutter and frame drops, especially on high refresh rate displays (120Hz/144Hz).
Recommendation: 1. Animate the palette webview container smoothly via CSS transform/width. 2. Update the native OS window geometry once at the end of the transition, or throttle native calls to 60 ms intervals.
Remediation: Decouple the native Win32 window resizing from per-frame rAF ticks. Allow the React container to ease visually, and dispatch native window bounds adjustments on animation settle.
Medium Concurrency & Reliability Shell Integration

Cascading synchronous thread sleep during taskbar pin retries

src-tauri/src/apps.rs:1997-2018, 2039-2086
In apps.rs, wait_for_taskbar_state polls Explorer's pin state 20 times with std::thread::sleep(100ms), totaling up to 2.0 seconds. The function set_taskbar_pinned cascades through three sequential strategies if preceding methods fail: 1. shell_bridge_taskbar_pin (waits up to 1.5s) 2. modify_taskband_pin (waits up to 2.0s) 3. shell_execute_verb (waits up to 2.0s) When an item cannot be pinned (e.g., restricted system targets or unresponsive shell hooks), the blocking thread sleeps for up to 5.5 - 6.0 seconds. This monopolizes Tokio's spawn_blocking thread pool workers.
Remediation: Introduce a shared deadline timeout across all three fallback strategies (maximum 1.5 seconds cumulative), or make the state check event-driven via shell notifications.
Medium Security & IPC Explorer Shell Bridge

TOCTOU race and unauthenticated file exchange in shared temporary directory

src-tauri/src/win_key.rs:465-475 & src-tauri/shell-hook/src/lib.rs:270-280
To instruct the injected shell hook in Explorer to pin or unpin an application, Prism writes the target path to %TEMP%\Prism\taskbar-pin-target.txt and sends a thread message (PostThreadMessageW). The Explorer hook callback then reads the plain file from disk. Because %TEMP% is shared across processes, there is no file locking, integrity validation, or unique transaction token. A local race condition or unprivileged process tampering could cause Explorer to execute shell verbs on an unexpected path.
Remediation: Relocate the payload exchange file to Prism's private, ACL-protected local application data directory (%LOCALAPPDATA%\app.prism.launcher), and incorporate a random transaction nonce in the message parameters.
Low System Edge Cases Elevation

Script and path argument escaping fragility in elevated launch command construction

src-tauri/src/apps.rs:1826-1841
elevated_command formats command-line arguments for scripts using raw string interpolation: format!("/d /s /c \"\"{path}\"{trailing_args}\"") for batch files, and format!("-NoLogo -NoProfile -File \"{path}\"{trailing_args}") for PowerShell. If a script path or shortcut argument contains unescaped double quotes, ampersands, or caret symbols, the command parser can misinterpret boundaries, leading to launch failures or truncated parameters.
Remediation: Sanitize and escape embedded quotation marks and special CLI delimiters in both path and trailing_args prior to formatting.
Low UI Polish & Accessibility WCAG 2.5.5

Interactive controls violate minimum 44px touch/pointer hit target standard

src/components/ui.tsx:144, 260
Several interactive controls in the UI have bounding boxes below the recommended 44x44px target size: - Toggle button is strictly 24px height by 40px width. - IconButton is 32px by 32px (h-8 w-8). While desktop mouse cursors provide higher precision, Windows tablet mode, touchscreens, and accessibility standards (WCAG 2.5.5 / 2.5.8) require expanding the hit target.
- className="focus-ring relative h-[24px] w-[40px] cursor-pointer rounded-full..." + className="focus-ring relative h-[24px] w-[40px] cursor-pointer rounded-full after:absolute after:-inset-2.5 after:content-['']..."
Remediation: Add invisible pseudo-element expansion (after:absolute after:-inset-2) to interactive toggles and icons to maintain visual density while providing a 44px hit target.

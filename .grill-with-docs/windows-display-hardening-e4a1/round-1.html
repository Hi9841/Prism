Hardening Prism across Windows displays.

Settle the native sizing contract, mixed-DPI transitions, and viewport degradation rules before changing native window code.

Round 1 · 5 architectural decisions

1. What is the minimum supported display baseline?

Prism cannot guarantee perfect display on arbitrary ultra-small screens or extreme scaling. What is the guaranteed floor, below which Prism degrades gracefully into a compact mode?

Recommended: 800×600 effective work area. Supports common laptops (1080p at 150% = 1280×720 work area, or 1366×768 at 125% = 1092×614) while accommodating docked taskbars and tablets.

2. What unit contract governs native sizing and IPC?

In lib.rs:1241, set_window_width assigns incoming values to PhysicalSize while frontend treats them as logical CSS pixels. Which unit should be authoritative everywhere in settings and IPC?

Recommended: Logical DIP everywhere. Settings, IPC, and frontend use logical CSS pixels. Rust converts to physical pixels strictly at Win32/Tauri boundaries using monitor DPI.

3. How should Prism behave when moving across mixed-DPI monitors?

When a user summons Prism or drags it between monitors with different scale factors (e.g. 150% laptop vs 100% external display), how should geometry adjust?

Recommended: Preserve logical DIP size. The launcher retains its identical logical layout and relative screen size, recalculating physical dimensions on the target monitor.

4. How should Prism adapt when work-area height is shorter than the launcher?

Under high display scaling (200%), vertical orientation, or thick taskbars, available vertical work area may be less than the standard 620px. How should the native window and UI adapt?

Recommended: Clamp window height and scroll results. Native window clamps to work area; search bar remains fixed, results list scrolls smoothly with stable gutter.

5. What is the contract between view zoom and the native window frame?

In bridge.ts:86, setViewZoom alters webview zoom between 70% and 150%. Should zooming also resize the native OS window frame?

Recommended: Content zoom only; decouple window geometry. View zoom scales content inside the fixed launcher frame. Launcher width presets (640/720/800) control window geometry.
